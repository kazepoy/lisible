# Developer guide

*English · [Français](../fr/manuel-developpeur.md)*

## 1. Overview

Lisible is a **Manifest V3 Web Extension** with no dependencies. A single source (`extension/`) serves every browser; `scripts/build.mjs` derives one build per browser into `dist/` (ignored by git).

For Safari, the extension must ship inside a **container app** (macOS, iOS), generated by Apple's `safari-web-extension-converter` tool and not versioned (`xcode/` folder, ignored by git).

```
extension/
  manifest.json
  shared/settings.js   settings model (no DOM, testable in Node)
  shared/style.js      CSS generation (pure functions)
  content/content.js   injected into every page and iframe (document_start)
  shared/ui.js         shared UI helpers (storage, translations, control binding)
  shared/ui.css        shared styles (colours, switches, sliders, swatches)
  popup/               popup: simple settings, “All sites” / site tabs
  options/             “More settings” page: fine-grained settings, My sites, About
  background.js        keyboard shortcuts (ES module)
  fonts/               Latin WOFF2 400/700 (+ italic) and OFL licences
  icons/               extension and toolbar icons
  _locales/fr|en/      UI strings (French by default)
scripts/build.mjs      Chrome / Firefox / Safari builds + zips (dist/)
scripts/captures.mjs   documentation screenshots (docs/images/)
scripts/creer-projet-xcode.sh
tests/                 node:test + Playwright
LICENSE                PolyForm Noncommercial 1.0.0 (code); fonts under OFL
assets/app-icon-1024.png
```

## 2. Architecture

```
popup.js ───┐
options.js ─┼─writes──▶ storage.local["lisible"] ──onChanged──▶ content.js ──▶ <style> + reading ruler
background.js ┘ (shortcuts)                                      (every page and iframe)
```

- **Single source of truth**: the `storage.local["lisible"]` object. The popup, the settings page and the background never talk to pages directly: they write the state, and each content script reacts to `storage.onChanged`. The popup and the settings page also keep each other up to date this way (`createStore` in `shared/ui.js`).
- **Global namespace** `Lisible`: `shared/settings.js` creates it, `shared/style.js` adds `Lisible.style` and `shared/ui.js` (UI pages only) adds `Lisible.ui`. They are classic scripts, so they can be loaded as content scripts, with `<script>` in the UI pages, via `import` in the background (module) and via `require` in the tests.
- **Only message exchanged**: `{ type: 'lisible:getHost' }`. The popup and the background ask the main page for the current site when `tab.url` is not available (depending on the permissions granted in Safari).

### Data model

```js
{
  version: 2,
  enabled: true,            // main switch
  global: { ...settings },  // shared text settings
  ruler: { enabled, mode, height, opacity, color },  // reading ruler, shared
  sites: {
    'example.com': { enabled?: false, settings?: { ...settings } }
  }
}
```

- `Lisible.resolve(state, host)` returns `{ active, custom, settings }`. It is the only “on or off for this site” decision logic.
- Site names are normalised by `normalizeHost`: lowercase, no `www.`. `file://` pages have the site `file`.
- In an iframe, the site used is the tab's site, so that per-site exceptions also apply to embedded frames (see part 6 for Firefox).
- Everything read from storage goes through `sanitizeState` / `sanitizeSettings` / `sanitizeRuler`: bounded values, closed lists, `#rrggbb` colours.
- **Migration from version 1**: the old `bold` / `alignLeft` fields are converted; the ruler (`global.ruler*`) moves to `state.ruler`; the “chosen sites” mode (`scope`) and the “Always” exception (`enabled: true`) are dropped.
- **Spacing levels** (`SPACING_LEVELS`): *Normal / Wide / Extra wide* set letters, words, line height and paragraphs together. `spacingLevel(s)` finds the level, or `null` after fine-tuning.

### CSS generation (`shared/style.js`)

- `buildCSS(settings, urlFor, root)` produces all the CSS. `root` is `html.lisible-on body` on pages and `#preview` in the preview of the “More settings” page: **the preview uses exactly the same code as the pages**.
- **Neutral value**: a property is only emitted if its value differs from `Lisible.NEUTRAL` (or from `'default'` for fixed choices). A page is never changed for nothing.
- Every declaration is `!important` to win over the sites' CSS.
- **Font exclusions** (`FONT_EXCLUDE`): code, formulas, SVG, `:empty` elements (almost always icons drawn with `::before`) and common icon classes.
- **Fonts**: `@font-face` rules built with `runtime.getURL`; the files are listed in `web_accessible_resources`.
- **Reading ruler**: it is attached to `<html>`, outside `<body>`, so that neither the text-size `zoom` nor the themes affect it. Its container has `mix-blend-mode: multiply` so that text under the band keeps its contrast.

## 3. Adding a setting

1. **`shared/settings.js`**
   - add the default value to `DEFAULT_SETTINGS`;
   - depending on the type: the bounds in `RANGES` (number), the list in `CHOICES` (fixed choice), or the boolean or colour lists in `sanitizeSettings`;
   - for a number, add the “unchanged” value to `NEUTRAL` if there is one.
2. **`shared/style.js`**: emit the CSS in `buildCSS`, prefixed with `${R}` and only outside the neutral value.
3. **`options/options.html`** (and `popup/popup.html` only for an essential setting): add a control with `data-key="<name>"` (`range`, `checkbox`, `radio`, `select` or `color`). Reading and writing are automatic (`bindControls` / `renderControls` in `shared/ui.js`). For a slider, also add `<output data-for="<name>">`. A reading-ruler field uses `data-ruler` instead of `data-key`.
4. **`shared/ui.js`**: for a slider, add its display format to `FORMAT`.
5. **`_locales/fr` and `_locales/en`**: add the strings (`data-i18n="<key>"`).
6. **Tests**: sanitising and CSS in `tests/settings.test.js`, real rendering in `tests/e2e.test.js`.

**UI layout**:
- **Popup**: header (main switch), reading ruler (settings folded), *All sites / site* tabs, four simple settings (font, size, spacing, background), footer (*More settings*, *Reset*), and an *Undo* bar after each change. When the site tab is active and the site has its own settings, the `editing-site` class turns the accent purple (`--accent: var(--site)`).
- **“More settings” page** (`options_ui`, opened in a tab): reading ruler, *You are editing* selector, preview, fine-grained setting sections, *My sites*, *About*. `options.html#site=example.com` opens it on that site's settings.

## 4. Adding a font

1. Get the WOFF2 files under a free licence, for example with `npm pack @fontsource/<font>`, and copy `files/<font>-latin-{400,700}-{normal,italic}.woff2` into `extension/fonts/`.
2. Copy the licence into `extension/fonts/licenses/`.
3. Declare the font in `FONTS` (`shared/settings.js`): `family` (prefixed with `Lisible ` to avoid clashing with a site's font), `file`, `italic`, `fallback` and `author`. The licence must be named `fonts/licenses/<file>-OFL.txt`: the *Credits and licences* section of the “More settings” page links it automatically.
4. Add an `@font-face` to `shared/ui.css` for the font sample in the UI pages.
5. Check coverage of French characters (`éèàçœ«»’…`), for example with `fontTools`.

## 5. Translations

- Strings live in `_locales/<language>/messages.json`, with French as the default (`default_locale`).
- `applyI18n` (`shared/ui.js`) replaces the content of `data-i18n` elements, the `title` of `data-i18n-title` elements and the `aria-label` of `data-i18n-label` elements. The text written in the HTML is the fallback.
- To add a language: create `_locales/<code>/messages.json` with **all** the French keys.

## 6. Per-browser builds

```bash
npm run build            # or: node scripts/build.mjs chrome|firefox|safari
```

`extension/manifest.json` is Safari's manifest; the script derives the others from it:

| Browser | Differences |
|---|---|
| **Chrome / Edge** | `background.service_worker` (Chrome refuses `background.scripts`), `minimum_chrome_version: 111` (for `color-mix()`) |
| **Firefox** | `browser_specific_settings.gecko`: id `lisible@lisible-extension` (never change it once published), minimum version 140, “no data collected” declaration required by addons.mozilla.org; `gecko_android`: Firefox for Android 142+ |
| **Safari** | none; the Xcode project uses `extension/` directly |

Differences handled in the code:
- **Iframes**: Firefox has no `location.ancestorOrigins`. The content script then reads `window.top.location` when it is the same origin, otherwise `document.referrer`.
- **Shortcuts**: Firefox for Android has no `commands` API, hence the `api.commands?.…` call in `background.js`.
- **APIs**: `globalThis.browser || globalThis.chrome`. The APIs used return promises in all three browsers under Manifest V3.

**Trying without publishing:**
- **Chrome / Edge**: `chrome://extensions`, *Developer mode*, then *Load unpacked* → `dist/chrome`.
- **Firefox**: `about:debugging`, then *This Firefox* → *Load Temporary Add-on* → `dist/firefox/manifest.json`. Or `npx web-ext run --source-dir dist/firefox`.
- **Firefox for Android**: phone with USB debugging, then `npx web-ext run -t firefox-android --source-dir dist/firefox` (see the `web-ext` documentation for device options). Not tried yet.

## 7. Tests

```bash
npm test              # unit + end-to-end + real Chrome build
npm run test:unit     # unit tests only (Node only)
npm run lint:firefox  # validation of the Firefox build by Mozilla's tool
npm run captures      # regenerates the screenshots in docs/images/ (fr and en)
```

- `tests/chrome.test.js` builds `dist/chrome` and **actually loads it in Chromium**: service worker, content script, fonts, popup and settings page, with the real extension APIs.
- **Requirements**: Node 22 or later, and Playwright with Chromium for the end-to-end tests (`npm i -D playwright && npx playwright install chromium` if they are not already installed).
- `tests/fixtures/browser-shim.js` simulates `storage`, `runtime`, `tabs` and `i18n`. Content scripts are injected as at `document_start`, with `addInitScript`.
- **What the tests do not cover**: Safari (per-site permissions, sites' CSP, iOS popup), real execution in Firefox and Firefox for Android, and Edge. Check by hand before each release.

## 8. Safari: build, run, debug (Mac + Xcode)

```bash
./scripts/creer-projet-xcode.sh com.mydomain.lisible
open xcode/Lisible/Lisible.xcodeproj
```

- The project **references** `extension/` without copying it. Just *Run* again after a change; no need to regenerate.
- Regenerate the project only if the structure changes (a new folder at the root of the extension, for example). The `--force` option overwrites `xcode/`.
- **Signing**: choose a team in *Signing & Capabilities* for each target (app and extension, macOS and iOS).
- **Debugging on macOS**: enable the *Develop* menu (*Settings > Advanced*), then *Develop > Allow Unsigned Extensions* for an unsigned build. The page's Web Inspector shows the content script; the *Develop* menu gives access to the background and the popup.
- **Debugging on iOS**: turn on *Settings > Apps > Safari > Advanced > Web Inspector* on the device, connect it to the Mac, then use Safari's *Develop* menu on the Mac.
- If the converter rejects an option of the script, `xcrun safari-web-extension-converter --help` shows the syntax of the installed version.

## 9. Publishing

**All browsers**
1. Update `version` in `extension/manifest.json`, then run `npm run build` and `npm test`.

**Chrome Web Store, Edge Add-ons, addons.mozilla.org**: upload the matching zip from `dist/` (`lisible-chrome-<version>.zip` for Chrome and Edge, `lisible-firefox-<version>.zip` for Firefox). As far as I know, to be checked, publishing is free on Firefox and Edge, and costs a one-time $5 on Chrome. Firefox may ask for the source code: the repository is enough, since there is no minification or bundler. Licence: choose a custom licence and paste the text of `LICENSE` (PolyForm Noncommercial 1.0.0 is not in AMO's list).

**App Store (Safari)**
1. Update the version and build numbers in Xcode.
2. Run `npm test`, then check by hand on Mac, iPhone and iPad.
3. *Product > Archive* for each platform, then upload to App Store Connect.
4. The app icon (1024 × 1024) is `assets/app-icon-1024.png`.
5. **Privacy**: the extension collects no data. It asks for access to all sites so that it can apply everywhere; this must be justified in the App Store listing.

## 10. Conventions

- **Code**: JavaScript with no framework or bundler. Comments in French; UI strings in French and English.
- **Documentation**: in French (`README.fr.md`, `docs/fr/`) and English (`README.md`, `docs/en/`). Every change must be made in both languages.
- **CSS**: every new page rule must be prefixed with the `${R}` root and emit nothing at the neutral value.
- **Storage**: never read storage without going through `sanitizeState`.
- **Commits**: messages in French, in the imperative (“Ajoute…”, “Corrige…”).
